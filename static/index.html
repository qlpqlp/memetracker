How MemeTracker works

          
MemeTracker connects to the Dogecoin P2P network and watches the mempool first (inventory and raw transactions). Headers and tip-block scans are only a backup if a payment skips mempool relay and is mined immediately. When a transaction pays one of your tracked P2PKH-style outputs, the app records txid, time, and DOGE amount and stores it under your data directory.

          
Dashboard

          
Summary counters plus live trend charts (mempool visibility, connected workers, stored rows and tracked addresses) built from browser polling while you keep the dashboard open. Header safeguard stats show tip hash/time, headers kept, blocks scanned, and payments first seen from blocks.

          
Start / Stop

          
Start writes memetracker_config.json and launches workers. Stop signals workers to exit between connections (an active peer session may take a short while). A complete config file on disk can auto-start P2P when the process launches.

          
Configuration

          
Adjusts retention and per-address tx cap in settings.json without restarting P2P.

          
Tracked addresses

          
Add or refresh a watched P2PKH address (same as GET|POST /track/{address}), and manage the on-disk list. Remove deletes the address file and its stored txs. The Transactions table lists matched payments only, not every mempool transaction.

          
Transactions

          
On-disk mirror of detected payments to watched addresses. Mempool size on the dashboard is a visibility counter. Peers & mempool shows the latest raw tx bodies downloaded for matching.

          
Header / block safeguard

          
Backup only. Mempool watching always has priority. Workers track tip headers (sendheaders / getheaders), save the verified tip to header_tip.json, and only scan a recent tip block body when mempool traffic is quiet. That catches watched payments that skipped mempool relay and went straight into a block. This is not a full chain sync and must not starve mempool getdata.

          
Double-spend detection (mempool)

          
MemeTracker also checks transaction inputs while watching live mempool traffic. If two or more mempool transactions spend the same previous output (same prev_txid:vout), they are flagged as a conflict and shown with a red Double spent detected badge. This check is live-window only: once transactions disappear from the current mempool tracking window, they are no longer actively compared. The feature is intended for transactions related to watched payment addresses.

          
Access control

          
User token: /track/{address} and /healthz. Admin token: web UI and /api/*. Shared IP whitelist grants full access. Unauthorized = Access denied only.

        

        

          
HTTP API reference

          
Replace BASE with your server origin, e.g. http://127.0.0.1:33555.

          
Status & health

          
curl -s BASE/healthz
curl -s BASE/{user_token}/healthz
curl -s BASE/{admin_token}/api/status

          
Start / Stop P2P

          
curl -s -X POST BASE/api/start -H "Content-Type: application/json" -d "{\"http_port\":33555,\"http_bind\":\"0.0.0.0\",\"network\":\"mainnet\",\"storage_dir\":\"\",\"list_limit\":10,\"retention_days\":7,\"p2p_host\":\"\",\"p2p_port\":22556,\"p2p_parallel\":3,\"p2p_log\":1,\"user_token\":\"\",\"admin_token\":\"\"}"

curl -s -X POST BASE/api/stop

          
Runtime limits

          
curl -s -X POST BASE/api/config -H "Content-Type: application/json" -d "{\"list_limit\":20,\"retention_days\":14}"

          
Access control

          
curl -s -X POST BASE/api/allowlist -H "Content-Type: application/json" -d "{\"api_allowed_ips\":[\"127.0.0.1\"],\"user_token\":\"user-token\",\"admin_token\":\"admin-token\"}"

          
Track address (user)

          
curl -s "BASE/track/YourP2PKHAddress"
curl -s "BASE/{user_token}/track/YourP2PKHAddress"

          
User token: /track + /healthz. Admin token: web UI + /api. Shared IP whitelist = full access.

          
Double-spend flag in API data

          
In /api/status, each item in transactions includes double_spent, confirmed, and confirmations (0-5, from headers/blocks after inclusion).

          
Header safeguard in API data

          
Object header_safeguard includes tip hash, tip height (when known), tip time, headers kept, blocks scanned, confirmed_hits, and whether the tip was resumed from disk.

          
Remove address / tx row

          
curl -s -X DELETE "BASE/api/addresses/{hash160_hex}"
curl -s -X DELETE "BASE/api/transactions?txid=...&hash160_hex=..."

          
All API responses are JSON unless noted. Errors include an error string. A complete memetracker_config.json shape is required for /api/start; you may include api_allowed_ips, user_token, and admin_token.
